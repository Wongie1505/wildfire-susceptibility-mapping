PHASE 1: INPUT CHECK
====================

Status: COMPLETE. Boundary and fire archive pass. Predictor grid problems
handled in Phase 1b. NDVI and NDMI handled in Phase 1c.


1. PURPOSE
----------
Before any analysis, confirm that every raw input opens, has a usable
coordinate system, overlaps the study boundary, and has the expected
pixel size. Record the result for every file, so a later problem can be
traced back to its source.


2. WHAT WAS DONE
----------------
The script phase1_input_check.py was run on the input folder. For each file
it recorded: CRS, width, height, pixel size, extent, nodata value, data type,
share of nodata pixels, whether the grid matches the reference DEM, and whether
the raster overlaps the boundary. The boundary area and the fire-record checks
(date range, instruments, confidence values, detections inside the boundary)
were recorded in the same report.

Folder: Phase_1_inputs/
Script: phase1_input_check.py
Output: outputs/inputs_check.csv

             Viphya_DEM.tif, Viphya_Slope.tif

             viphya_ndmi.tif, viphya_ndvi.tif, viphya_rainfall.tif

All 8 failures had the same cause: the grid (pixel size and origin) differed
from the reference DEM. The CRS (EPSG:32736) was correct on all 12 files, and
all 12 overlapped the boundary.


5. WHY IT MATTERS
-----------------
Every raster in the model must share one grid. If the grids differ, each
sample point reads a value from a slightly different place in each layer,
and the predictor table becomes inconsistent. The failures were fixed in
Phase 1b and Phase 1c rather than silently accepted.
